# sc-dataset-qualification-review

Second, independent opinion on a completed first qualification. The reviewer
judges the qualifier's work — it must not mechanically replay it, and prior
audit proposals are material, never pre-approved decisions.

## Position in the pipeline

Runs strictly AFTER the first qualification has been persisted
(`geo_database.py save-qualification`) and BEFORE envelope seal. The tool
enforces this: `geo_review.py save-review` refuses with `qualification_missing`
when no original rows exist. Never modify `geo_qualification` or
`geo_sample_qualification` rows; review results are append-only in
`geo_review_runs` / `geo_review_decisions`.

## Inputs

- Production DB (`data/geo.duckdb`) — read the first-pass decisions and full
  GSM arrays (`get-qualification`, `get-sample-qualifications`).
- The source run dir (`data/reports/run_<source_run_id>/`) — frozen SOFT
  raw+parsed artifacts, evidence.jsonl; these are the GEO snapshot of record.
- `review_run_id` — generated by `geo_envelope.new_run_id()`; a NEW directory
  `data/reports/run_<review_run_id>/` holds review artifacts.

## Prerequisites (safety gate, in order)

1. `geo_review.py --db data/geo.duckdb ensure-schema` (idempotent DDL add).
2. `geo_review.py backup` — refuse to continue unless the backup file with
   sha256 exists; record path in the review report.
3. Confirm no concurrent pipeline writers (`ps` + brief exclusive connect; a
   busy lock means STOP, not retry-loop).
4. Snapshot counts of the original tables (stored in `report`/`notes`).

## Scope and priorities

- Priority 1: every `uncertain` at GSE level and every `uncertain` GSM.
- Priority 2: `include`/`exclude` rows only when a concrete suspicion exists
  (named in the report: e.g. classifier token gap, SuperSeries ownership,
  bulk/spatial markers inside an include, colon markers inside an exclude).
- Whole population is examined; any narrowing must be declared, never silent.

## Staged evidence recovery (escalate only on need)

- **T0 (free, local)**: re-derive from already-stored fields with
  `review_rules.py` predicates — ALL site-ish keys (`site`, `sampling
  location`, `region`, `location`, `organ`, `tissue`), spaced values
  (`C o l o n`), underscore variants (`ascending_colon`); modality tokens in
  titles/protocols (`10X Chromium`, `scBCR`/`scTCR`, `total RNA`), platform
  titles from frozen SOFT. Most unresolved cases close here.
- **T1 (cheap network)**: GEO-linked `pubmed_id` abstracts (eutils efetch);
  title-search for records with no link. A publication linked to a GSE does
  NOT prove every GSM comes from the described experiment — cohort statements
  apply to GSMs only when the record ties them (same series, uniform
  protocol) — write that justification into `sources`.
- **T2 (targeted)**: only needed supplementary files (README, metadata.csv,
  feature reference), stored under the review run dir with size+sha256;
  never bulk-expression archives; never mass downloads.
- **T3 (last)**: BioSample/SRA attributes; record negative results.

## Decision rules

- Allowed statuses: `include`, `exclude`, `uncertain` only.
- Change a status ONLY on sufficient evidence; every changed row needs
  non-empty `reason` AND `sources` (each: source, location, applies_to
  `dataset|gsm`, detail). Uncertain rows need `missing_info` stating exactly
  what is absent and why recovery failed.
- Missing information is NOT evidence of exclusion; absence of a word in a
  cohort text is not a per-GSM verdict either.
- Conflicts (GEO vs publication, bulk files vs scRNA claims) stay `uncertain`
  with BOTH sides cited — the reviewer flags, never guesses. Do not
  auto-resolve; report to the user.
- GSM independence: a dataset may combine colon/blood, GEX/VDJ, human/mouse,
  tissue/cell line; decide each GSM from its own fields, dataset status is
  derived (>=1 eligible GSM => include possible; all decisive-exclude =>
  exclude; never uncertain as a silent fallback).
- Project biological criteria are fixed: Homo sapiens; scRNA-seq/snRNA-seq
  (spatial-only, repertoire-only, protein-only, bulk do not qualify); CD/UC/
  IBD relevance (incl. controls within a relevant study); colon/colonic
  segment tissue incl. rectum; blood/PBMC/ileum/appendix/mesentery/etc.
  excluded. Cell lines / iPSC-derived / xenograft models: not established
  human colon tissue → uncertain with criteria-gap note; report, do not
  invent rules.

## Persistence (append-only, transactional)

- Draft `review_input.json` per the tool schema; run
  `save-review --review-run-id RID --source-run-id SRC --input FILE --skill-md <this file> --dry-run`
  first and reconcile `would_insert`/`would_change` with the draft; then run
  without `--dry-run` and immediately `validate` + `report`.
- Tests/dry-run mode of the pipeline: validation suite uses temp DBs only;
  production writes happen exclusively through `save-review` after backup.

## Outputs

- `data/reports/run_<review_run_id>/review_results.json` (full adjudication
  incl. T0-T3 evidence chains and provenance of downloaded files).
- `REVIEW_REPORT.md`: counts by proposed status and reason code, changed
  GSE/GSM lists with before/after, retained-uncertain with missing_info,
  conflicts, backup path, DB validation results, original-rows-unchanged
  proof (counts+checksums before/after).

## Prohibitions

- No resets, deletes or overwrites of production rows; no schema edits beyond
  the review tables; no re-running GEO search; no changing biological criteria
  without user approval; no trusting prior proposals as decisions; no silent
  scope narrowing.
